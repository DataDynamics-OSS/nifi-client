① 토큰 만료

NiFi의 JWT는 기본 12시간 뒤 만료됩니다. OkHttp는 401을 받으면 Authenticator를 부르고, 그것이 돌려준 요청을 다시 보냅니다. 이 앱의 Authenticator는 그때 AccessApi.createAccessToken으로 로그인합니다. 같은 요청을 두 번 넘게 보내지 않고, 로그인 요청 자체가 거절되면 포기합니다.

OkHttpClient http = client.getHttpClient().newBuilder()
        .authenticator((route, response) -> {
            if (response.priorResponse() != null) return null;     // 이미 한 번 다시 보냄
            String token = new AccessApi(client).createAccessToken(user, password);
            client.setAccessToken(token);
            return response.request().newBuilder()
                    .header("Authorization", "Bearer " + token).build();
        })
        .build();
client.setHttpClient(http);

③ 예외를 구분하는 법

  • 404: 없는 id. 400: 요청이 틀림(revision, 비밀번호). 401: 토큰 없음·만료.
  • 409: 요청은 맞지만 지금 상태에서 할 수 없음(실행 중, 모르는 타입, 지원하지 않는 기능).
  • getCode() == 0: 응답이 없음. getCause()가 UnknownHostException, ConnectException, SocketTimeoutException 등입니다.

④ revision과 clientId

NiFi는 변경 요청의 revision을 서버의 것과 비교합니다. version이 같으면 받아들이고, 다르더라도 clientId가 마지막으로 고친 클라이언트와 같으면 받아들입니다(같은 화면에서 연달아 저장하는 경우를 위해). 그래서 여러 프로그램이 같은 흐름을 고친다면 프로그램(또는 세션)마다 다른 clientId를 쓰세요. flow.generateClientId()로 받을 수 있습니다.

clientId를 비워 두면 서로 다른 프로그램도 충돌을 감지하지만, 같은 clientId를 여러 곳에서 공유하면 서로의 변경을 조용히 덮어씁니다.
