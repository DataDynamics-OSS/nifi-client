예외는 ApiException 하나

swagger-codegen이 만든 클라이언트는 모든 실패를 checked 예외 ApiException 하나로 던집니다. 예외 타입으로 나눌 수 없으므로, 아래 값으로 구분합니다.

값뜻
getCode()NiFi가 돌려준 HTTP 상태. 응답을 받지 못했으면(연결 실패, 시간 초과) 0
getResponseBody()NiFi가 보낸 오류 문장(평문). 예: Unable to find processor with id '…'
getCause()응답을 받지 못했을 때의 I/O 예외(UnknownHostException, SocketTimeoutException …)
getMessage()HTTP 상태 문구 또는 원인 예외의 toString()

NiFi가 자주 돌려주는 상태

상태언제
400잘못된 요청, 낡은 revision("is not the most up-to-date revision"), 틀린 비밀번호
401토큰 없음·만료
403권한 없음(멀티 유저 설정에서)
404없는 컴포넌트 id
409지금 상태에서 할 수 없는 일: 실행 중인 프로세서 삭제, 데이터가 남은 연결 삭제, single-user에서 사용자 관리 등

오류 상자 읽는 법

  • 굵은 글씨: 예외 클래스 이름. 맨 아래 회색 글씨가 전체 이름입니다.
  • HTTP 배지: NiFi가 돌려준 상태 코드. 응답이 없으면 "응답 없음"입니다.
  • NiFi 메시지: 응답 본문의 오류 문장. 원인은 대부분 여기에 있습니다.
  • 원인: 응답을 받지 못했을 때의 I/O 예외.

코드에서 처리하기

try {
    processors.getProcessor(id);
} catch (ApiException e) {
    if (e.getCode() == 404) {
        // 없는 경우 처리
    } else if (e.getCode() == 0) {
        log.warn("NiFi에 연결하지 못함", e.getCause());
    } else {
        log.warn("NiFi {}: {}", e.getCode(), e.getResponseBody());
    }
}
