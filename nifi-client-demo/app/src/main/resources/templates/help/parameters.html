파라미터 컨텍스트란?

파라미터 컨텍스트(parameter context)는 이름-값의 묶음입니다. 프로세스 그룹에 하나를 연결하면, 그 그룹 안 컴포넌트의 속성에서 #{이름}으로 값을 씁니다. 개발·운영 NiFi에 같은 흐름을 두고 컨텍스트만 바꾸는 식으로 씁니다.

demo-params { env=demo, greeting=hello … }
     ▲ 연결
demo-flow
  generate.Custom Text = {"greeting":"#{greeting}", …}
  tag.env              = #{env}

값 바꾸기는 비동기

파라미터를 쓰는 프로세서는 값이 바뀌는 동안 멈춰 있어야 합니다. 그래서 NiFi는 변경을 update 요청으로 받아 "멈춤 → 값 바꿈 → 다시 시작"을 차례로 하고, 클라이언트는 완료될 때까지 조회한 뒤 요청을 지웁니다.

생성된 ParameterContextDTO에는 id 설정자가 없습니다(스펙에서 읽기 전용). 그런데 NiFi는 update 요청 본문에 component.id를 요구합니다(없으면 400 "Parameter Context's ID must be specified"). 그래서 방금 읽은 DTO를 그대로 고쳐 보냅니다.

따라 해 보기

  1. demo-params에서 env=staging으로 바꿉니다. 결과의 단계에서 updateSteps와 percentCompleted를 봅니다.
  2. 연결·큐에서 새 FlowFile의 env 속성이 staging인지 확인합니다.
  3. 연결된 컨텍스트를 삭제해 409를 봅니다.

이 화면이 쓰는 API

ParameterContextEntity ctx = parameters.getParameterContext(id, false);
ParameterContextUpdateRequestEntity update = parameters.submitParameterContextUpdate(
        new ParameterContextEntity().id(id).revision(ctx.getRevision())
                .component(ctx.getComponent().parameters(List.of(
                        new ParameterEntity().parameter(new ParameterDTO().name("env").value("staging"))))),
        id);
String requestId = update.getRequest().getRequestId();
try {
    while (!update.getRequest().isComplete()) {
        Thread.sleep(250);
        update = parameters.getParameterContextUpdate(id, requestId);
    }
    if (update.getRequest().getFailureReason() != null) { /* 실패 */ }
} finally {
    parameters.deleteUpdateRequest(id, requestId, null);
}
