실행 상태

상태뜻
RUNNING예약 주기마다 실행합니다.
STOPPED멈춤. 설정을 고치거나 삭제하려면 이 상태여야 합니다.
RUN_ONCE한 번 실행하고 STOPPED로 돌아갑니다. 시험용으로 좋습니다.
DISABLED시작 대상에서 빠집니다. 그룹 전체 시작에도 켜지지 않습니다.

멈추라고 해도 실행 중인 작업이 끝날 때까지 스레드가 남을 수 있습니다(활성 스레드). 그사이 삭제하면 409입니다.

설정 고치기와 revision

편집기의 JSON은 getProcessor 결과에서 고칠 만한 필드만 남긴 것입니다. revision은 읽은 시점의 값이므로, 다른 곳(NiFi UI 등)에서 먼저 고치면 저장이 400 "is not the most up-to-date revision"으로 거절됩니다. 이때는 다시 읽고 고칩니다.

  • 속성 하나를 지우려면 값으로 null을 보냅니다. 키를 빼면 "바꾸지 않음"입니다.
  • UpdateAttribute처럼 dynamic 속성을 받는 프로세서는 새 키를 넣으면 속성이 추가됩니다.

따라 해 보기

  1. tag 프로세서에서 STOPPED → 속성 env 값을 "#{env}-edited"로 바꿔 저장 → RUNNING.
  2. 연결·큐에서 새 FlowFile의 env 속성이 바뀌었는지 봅니다.
  3. 실행 중일 때 저장이나 삭제를 눌러 409를 확인합니다.

이 화면이 쓰는 API

ProcessorEntity p = processors.getProcessor(id);

// 멈추기: 최신 revision과 함께
p = processors.updateRunStatus(new ProcessorRunStatusEntity()
        .revision(p.getRevision())
        .state(ProcessorRunStatusEntity.StateEnum.STOPPED), id);

// 고치기: 바꿀 필드만 담아서
p = processors.updateProcessor(new ProcessorEntity()
        .revision(p.getRevision())
        .component(new ProcessorDTO().id(id)
                .config(new ProcessorConfigDTO().schedulingPeriod("30 sec"))), id);

ComponentStateEntity state = processors.getState(id);
processors.deleteProcessor(id, p.getRevision().getVersion(), clientId, null);
