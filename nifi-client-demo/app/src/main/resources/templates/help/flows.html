플로우 정의(flow definition)란?

프로세스 그룹 하나를 그 안의 프로세서, 연결, 컨트롤러 서비스, 파라미터 컨텍스트까지 묶어 JSON으로 적은 것입니다. id 대신 identifier(버전 관리용 id)를 쓰므로, 다른 NiFi에 올려도 새 id로 만들어집니다.

{
  "flowContents": { "name": "demo-flow",
    "processors": [ … ], "connections": [ … ], "controllerServices": [ … ] },
  "parameterContexts": { "demo-params": { … } },
  "externalControllerServices": { … }
}

업로드와 multipart

업로드 API는 multipart/form-data로 파일을 받습니다. 생성된 uploadProcessGroup(…, Object file, …)은 인자가 java.io.File일 때만 파일 파트로 보내므로, 문자열 JSON은 임시 파일에 써서 넘깁니다.

민감한 속성 값과 민감 파라미터 값은 내보낸 JSON에 들어가지 않습니다. 올린 뒤 다시 넣어야 합니다.

따라 해 보기

  1. demo-flow를 내보냅니다.
  2. 편집기에서 "schedulingPeriod" : "5 sec"를 "1 min"으로 바꿉니다.
  3. uploadProcessGroup을 누르고, 프로세스 그룹 화면에서 demo-flow-copy를 확인합니다(모두 정지 상태).

이 화면이 쓰는 API

String flowJson = groups.exportProcessGroup(groupId, true, false);

Path tmp = Files.createTempFile("flow-", ".json");
Files.writeString(tmp, flowJson);
try {
    ProcessGroupEntity copy = groups.uploadProcessGroup(
            parentGroupId, clientId, false, tmp.toFile(), "demo-flow-copy", 0d, 600d);
} finally {
    Files.deleteIfExists(tmp);
}
