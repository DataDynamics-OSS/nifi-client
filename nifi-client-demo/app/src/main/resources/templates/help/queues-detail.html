비동기 요청 패턴

큐 목록, 큐 비우기, 프로비넌스 검색, 파라미터 변경처럼 오래 걸릴 수 있는 일은 NiFi가 바로 답하지 않습니다. 클라이언트는 다음 세 단계를 직접 해야 합니다.

1. POST   …/listing-requests         요청 만들기 → id, finished=false
2. GET    …/listing-requests/{id}    finished=true가 될 때까지 반복
3. DELETE …/listing-requests/{id}    결과를 다 읽었으면 지우기 (서버 메모리 정리)
3단계를 빼먹으면 요청이 서버에 남아 있다가 시간이 지나야 사라집니다. finally에서 지우세요.

FlowFile 내용 받기

생성된 downloadFlowFileContent(…)는 스펙의 반환 타입이 StreamingOutput이라 Gson이 빈 객체를 만들 뿐 내용을 돌려주지 못합니다. 이럴 때는 같은 메서드의 …Call 버전으로 요청만 만들고 OkHttp로 직접 실행합니다. ApiClient가 만든 요청이므로 주소·인증 헤더·인터셉터는 그대로입니다.

삭제와 409

  • 큐에 데이터가 있으면 연결을 지울 수 없습니다. 먼저 비웁니다.
  • 출발이나 도착 프로세서가 실행 중이면 지울 수 없습니다. 먼저 멈춥니다.

이 화면이 쓰는 API

ListingRequestEntity listing = queues.createFlowFileListing(connectionId);
String requestId = listing.getListingRequest().getId();
try {
    while (!listing.getListingRequest().isFinished()) {
        Thread.sleep(250);
        listing = queues.getListingRequest(connectionId, requestId);
    }
    for (FlowFileSummaryDTO f : listing.getListingRequest().getFlowFileSummaries()) {
        FlowFileDTO ff = queues.getFlowFile(connectionId, f.getUuid(), null).getFlowFile();
        System.out.println(ff.getAttributes());
    }
} finally {
    queues.deleteListingRequest(connectionId, requestId);
}

// 내용: ...Call 메서드 + OkHttp
Call call = queues.downloadFlowFileContentCall(connectionId, uuid, null, null, null, null, null);
try (Response response = call.execute()) {
    String content = response.body().string();
}
