데모 구성

docker compose가 NiFi 2.12.0 하나를 HTTPS + single-user 로그인으로 띄우고, 이 앱은 생성된 Java 클라이언트 (io.datadynamics:nifi-client-v2)로 연결합니다.

demo-app ── ApiClient ──▶ nifi :8443 /nifi-api
            ├─ FlowApi, ProcessGroupsApi, ProcessorsApi …   (API 클래스는 ApiClient 하나를 공유)
            ├─ OkHttp 인터셉터: 요청 기록·메트릭
            └─ OkHttp Authenticator: 401이면 로그인 후 재전송

생성된 클라이언트의 구조

  • ApiClient: 주소(basePath), 인증, OkHttp 클라이언트, JSON(Gson)을 가집니다. 하나 만들어 공유합니다.
  • XxxApi: NiFi REST 리소스마다 하나(/processors → ProcessorsApi). 메서드 이름은 스펙의 operationId입니다.
  • 모델: XxxEntity(revision, 권한, 상태를 감싼 봉투)와 XxxDTO(컴포넌트 설정 본체).
  • 2.x 메서드는 (본문, 경로 파라미터) 순서로 인자를 받습니다. 1.x 클라이언트는 반대입니다.

연결 표 읽는 법

  • 인증서 검증 안 함: NiFi 이미지는 시작할 때 자체 서명 인증서를 만듭니다. 데모는 nifi.insecure-tls=true로 OkHttp에 모든 인증서를 믿게 했습니다. 운영에서는 CA를 신뢰 저장소에 넣으세요.
  • 토큰: 앱은 시작할 때 로그인하지 않습니다. 첫 호출이 401을 받으면 Authenticator가 AccessApi.createAccessToken으로 로그인해 토큰을 넣고 그 요청을 다시 보냅니다(요청 기록에서 시도 2). 토큰은 기본 12시간 뒤 만료되며, 그때도 같은 방법으로 다시 받습니다.
  • 확인: GET /flow/about이 답하면 UP입니다. /actuator/health의 nifi 항목도 같은 호출입니다.

데모 데이터

demo-flow  (파라미터 컨텍스트 demo-params: env, greeting)
  generate ──success──▶ tag ──success──▶ log
  GenerateFlowFile      UpdateAttribute   LogAttribute (정지)
  5초마다 JSON 하나     env=#{env}
  demo-json-reader, demo-json-writer (컨트롤러 서비스, 활성)

log는 일부러 멈춰 두었습니다. 그래서 tag → log 큐에 FlowFile이 계속 쌓이고, 연결·큐 화면에서 목록·내용 보기·비우기를 해 볼 수 있습니다. 모든 단계가 "이름으로 찾아 없으면 만들기"이므로 시드 다시 실행은 안전합니다.

이 화면이 쓰는 API

ApiClient client = new ApiClient().setBasePath("https://nifi:8443/nifi-api");
client.setAccessToken(new AccessApi(client).createAccessToken("admin", password));

FlowApi flow = new FlowApi(client);
String version = flow.getAboutInfo().getAbout().getVersion();
CurrentUserEntity me = flow.getCurrentUser();
ControllerStatusDTO status = flow.getControllerStatus().getControllerStatus();
SystemDiagnosticsEntity diag = new SystemDiagnosticsApi(client).getSystemDiagnostics(false, null, null);
BulletinBoardEntity board = flow.getBulletinBoard(null, null, null, null, null, 10);
